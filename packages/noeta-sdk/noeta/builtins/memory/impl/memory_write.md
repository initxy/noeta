Persist a named memory as a markdown file (reusing a name updates that memory; 'created'/'updated' dates are stamped automatically). Names must be slugs (letters, digits, '.', '_', '-'; no path separators; max 128 chars). Optional 'description' (a one-line summary shown in the memory index), 'type' (one of: user, project, procedural, reference) and 'keywords' (comma-separated retrieval aliases — include synonyms and cross-language equivalents, e.g. both English and Chinese terms, so auto-recall finds the memory whatever language the user writes in) are stored as frontmatter — pass them as parameters instead of writing a frontmatter block yourself. Reusing a name merges per-field: frontmatter fields this write does not mention are kept from the existing memory, so a body-only rewrite never drops them; to remove a field, start the text with a frontmatter block naming that key with an empty value (e.g. `---\ndue:\n---`). Without a description the first non-empty body line becomes the index summary. If the result lists similar existing memories, read and update those instead of keeping a near-duplicate. Writes are confined to the memory directory.
