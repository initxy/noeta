# 1.0 finish: fix the review findings, drop pre-release scaffolding, front ends as their own projects

## Goal

Fix what the 2026-11-04 four-way review found (kernel, extension surface, plugins), remove the
mechanisms and compatibility code that only served unreleased development builds, and move the
front ends out of the `noeta` package into their own top-level projects: a terminal UI, a web
app and a desktop app, each aligned with Claude Code's interface (DeepSeek Harness where Claude
Code has no counterpart). No over-design: the smallest mechanism that is correct wins; when a
case only leads into more machinery, cut the case and say so.

## Non-goals

- New agent capabilities beyond what Claude Code has.
- Mixed-version workers on one store (upgrades stay stop-the-world, `docs/server.md`).
- Benchmarks, release and push (owner sign-off items stay in `2026-10-29-open-source-follow-ups.md`).
- Native mobile apps; a Rust/Tauri toolchain (none on the build machine).

## Context

Review findings (2026-11-04, confirmed by reading the code): one reply's calls run past an
unanswered approval (`core/runner/calls.py` `run_calls`), and a waiting approval is re-gated on
every wake; `Extension.on_event` runs once and is lost on a crash, while
`examples/chat-bridge` claims at-least-once; tree holds (ADR-005/011/015/024/027) pin a whole
task tree to one worker and refuse background jobs by placement; Postgres claims scan idle
tasks, every append wakes every worker, running steps poll the inbox every 0.5 s; the folded
state keeps all history, so snapshots grow with the task's life; cross-plugin state reads are
untyped string lookups; `Tool` optional members are untyped `getattr`s; same-name tools shadow
silently; the sandbox protects only the first level of each working directory (nested repos'
`.git/hooks` writable); MCP: a cancelled starter cancels its co-waiters, SSE `endpoint` may
point off-origin with credentials, interrupts send no `notifications/cancelled`, an expired
HTTP session is never reconnected, stdio shutdown leaves grandchildren; `ExitWorktree` misses
untracked files under `status.showUntrackedFiles=no`; `WriteTool(allowed_path_globs)` is dead;
schema migrations for dev-only versions 2 and 3, and plugin-split read-back of
pre-split logs (`budget.FORMER_NAME`, compaction's `permissions.plan` fallback) serve logs only
the maintainer's machine has.

## Decisions

- D1 Holds are removed. A task that owns a live background job (or a parked MCP request) keeps
  its own claim while it waits: its worker renews the lease and takes the task's inbox itself,
  so no other worker can run it. Per task, not per tree: a parent stops a child's job by posting
  to the child, the child's worker acts. A worker that dies loses its jobs (as today); the next
  claimer tells the model the job is gone. If keeping a claim across a wait proves to need more
  than the runner's existing lease/inbox machinery, fall back to: a job ends with the task's
  claim (multi-worker deployments say so), never a new table. ADR supersedes 005/011/015/024/027.
- D2 Approvals are ordered: gating stops at the first `Ask`; calls after it are not started and
  are gated again once it is answered. The waiting ask is recorded so a wake does not re-run
  `before_tool` for it.
- D3 `on_event` is at-least-once for what a plugin marks delivered: the smallest mechanism the
  runner can carry (redelivery on pickup of events after the plugin's own recorded cursor), no
  separate outbox service. The chat-bridge example and `docs/extending.md` state the guarantee
  that actually holds.
- D4 Store schema: one migration remains, 0.6 (version 1) to 1.0; dev-only versions 2 and 3 and
  the "old binary rewrites the holds table" handling go. Pre-split log read-back goes.
- D5 Postgres: a partial claim index on claimable rows only; wake workers on `created` /
  `posted` / `released` only; no inbox polling while the store has a shared change feed.
  `TaskState.history` leaves the fold (rebuilt from the log where needed) if that is local;
  otherwise its own follow-up.
- D6 Cross-plugin reads go through typed readers in `noeta/toolkit` (one per published record);
  `Tool` optional members become one typed flags object with defaults; a tool-name clash logs a
  warning naming both plugins; hook failure semantics are a table in `docs/extending.md`.
- D7 Front ends are top-level projects outside the `noeta` package:
  - `tui/` — Python package `noeta-tui` (Textual, in process through `AppAPI`; `--server`
    for a remote one). `noeta` with no arguments finds it through the entry-point group
    `noeta.frontends` (name `tui`) and names the install line when missing.
  - `web/` — TypeScript, React + Vite, against the HTTP API (`noeta serve`); the server can
    serve the built bundle.
  - `desktop/` — Electron (no Rust toolchain for Tauri), wrapping the web build and starting a
    local `noeta serve` with its own token.
  Interface target: Claude Code's terminal UI for `tui/`; Claude Code's web/desktop app for
  `web/` and `desktop/` (sessions sidebar, transcript with tool cards and diffs, approval cards,
  permission-mode and model pickers, todo list, slash commands, @-mentions, image paste,
  rewind); DeepSeek Harness's where Claude Code has nothing. Each has its own tests; a missing
  HTTP route is added in `noeta/host` with tests.
- D8 `repetition_guard` stays (off by default, a host asked for it). `environment.py` is split
  in its own maintenance diff.
- D9 (D1 as built; no fallback needed) A kept wait is `Patch.keep` on W1's hand-back append:
  the row says `waiting`, owner, epoch and lease stay; claims skip unexpired leases. The run
  goes on in the background (`Runtime.run_claim` returns; a woken run takes a `concurrency` slot
  while it steps), renewing the lease and watching the inbox; a wake re-runs the pickup's start.
  A lapsed kept lease makes the task claimable at once (the next claimer posts `JOBS_LOST`,
  behind any end already in the inbox), so a crash still wakes the task; `Runtime.let_go` (a
  worker stopping) clears the lease and leaves the task waiting, told with its next message.
  A job's guard period is a third of its claim's lease, so it dies by the time the lease runs out. Cut: a sub-agent's jobs die with it (they used
  to report to the root, which needed the tree on one worker); `TaskStop` of a child's job
  reaches a running child only (`STOP_JOB`). ADR-029.
- D10 (D4) Schema version 5: any older store drops `holds` / `tree_holds` (and on Postgres the
  old claim index) and is current; no dev-only version 2/3 steps, no re-telling of holds.
- D11 (D5) `TaskState.history` is read by the request builder, compaction, checkpoints,
  memory, permissions, todos and tool search: not local, left in the fold (follow-up below).

## Acceptance criteria

- Every finding in Context is fixed with a test that fails without the fix.
- `make check`, `make parity` (0 mismatches), `make cluster` green; `tui/`, `web/`, `desktop/`
  each have a test command run by a `make frontends` target, green.
- No hold code or table remains; no migration for versions 2/3.
- `noeta` with no arguments opens the TUI when `noeta-tui` is installed.

## Risks

- D1 touches the runner's claim lifecycle; `make cluster` is the guard.
- Front-end "alignment" is judged by eye; each front end keeps its screenshots in its own directory.
